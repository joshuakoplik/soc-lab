## Notes on this first run

`corpus/attacks/` currently holds only the 3 trivially-benign proof-of-loader items
`SPEC.md` §9.5 calls for -- real attack content is maintainer-supplied and has not been
populated yet. That's why every row above is identical: none of the 3 items are actually
adversarial (each expects `refuse: false`), so none of the entitlement-layer or
hardened-prompt toggles have anything to defend against yet, and the one "leak" recorded in
every row is `example-indirect-harmless-plant` -- a deliberately harmless planted document
correctly becoming retrievable, which is the loader/pipeline working as designed, not a
security failure. This table will become a meaningful ablation comparison once real attack
content lands in `corpus/attacks/`; until then, its value is proving the full run -> score
-> report pipeline is real and correct end to end, on real model calls, for both configured
models across all three shipped control-vector configs.
